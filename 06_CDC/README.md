## 1. 亚稳态与 MTBF

### 1.1 为什么需要

两个时钟**没有确定的相位关系**（异步）时，源时钟域的信号可能在目的时钟沿附近的任意时刻变化。STA 无法为这种路径保证 setup/hold（`../07_STA/README.md` 第 11 节），违例迟早会发生。CDC 设计要解决的是：**违例发生了也不出功能错误**。

### 1.2 亚稳态是什么

触发器内部锁存数据的是一对交叉耦合的反相器，它有两个稳定点（0 和 1）和一个不稳定的平衡点（约 VDD/2）。数据在 setup/hold 窗口内变化时，内部节点可能被推到平衡点附近：

```
        输入在窗口内变化
               ↓
CLK   ________/‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾
Q     ════════╱ ─ ─ ─ ─ ─ ─ ─ ╲═════════════   正常：Tcq 后到 0 或 1
Q'    ════════ ~~~~~~~~~~~~~~~~~~~╱‾‾‾‾‾‾‾‾   亚稳：中间电平停留一段时间，最后随机落到 0 或 1
              |<---- 恢复时间 t ---->|
```

关键性质：

- **仍处于亚稳态的概率随时间指数下降**：P(t) ∝ e^(−t/τ)。τ 是工艺和单元决定的时间常数，通常只有几十皮秒。
- 最终落到 0 还是 1 是**随机的**；落定所需时间也是随机的，理论上没有上限。
- **不可消除，只能降低概率**。同步器做的是"多给它一点时间落定"。

亚稳态的真正危害不只是"值可能错"：一个亚稳的信号扇出到多个寄存器时，不同寄存器可能在同一个沿上读到不同的值（一个读成 0、一个读成 1），状态机就会进入非法状态。所以**同步器第一级的输出不能扇出给其它逻辑**。

### 1.3 MTBF 公式推导

MTBF（Mean Time Between Failures）：同步器平均多久失效一次。

1. 目的时钟每个周期采样一次，数据每次翻转落在宽度为 Tw 的危险窗口里的概率是 Tw / Tclk = Tw × fclk。
2. 数据每秒翻转 fdata 次，所以每秒进入亚稳态的次数 = Tw × fclk × fdata。
3. 进入亚稳态后，给它 Tr 时间还没落定的概率是 e^(−Tr/τ)，这才算真正失效。
4. 每秒失效次数 = Tw × fclk × fdata × e^(−Tr/τ)，取倒数：

```
MTBF = e^(Tr / τ) / (Tw × fclk × fdata)
```

| 符号 | 含义 | 怎么变大 MTBF |
|------|------|---------------|
| Tr | 留给亚稳态恢复的时间（resolution time） | 多加一级同步器 ≈ 多一个周期；同步器之间不放逻辑 |
| τ | 恢复时间常数 | 用专门的同步器单元（高增益） |
| Tw | 亚稳态窗口 | 工艺决定 |
| fclk | 目的时钟频率 | 频率越高，Tr 越短、采样越频繁，MTBF 急剧下降 |
| fdata | 异步数据翻转频率 | 减少跨域信号的翻转 |

Tr 在指数上，所以它是决定性因素。

### 1.4 例题（`lab/MTBF/mtbf.py` 的真实输出）

示例参数：τ = 20 ps，Tw = 30 ps，Tcq = Tsu = 0.1 ns，fdata = 50 MHz（教学用的示例值，真实值由工艺厂或库特征化给出）。

Tr 的口径（保守）：1 级时，采样后的 Q 直接进组合逻辑，只剩下游路径的余量 T − Tcq − Tsu − Tlogic；N 级时，级间没有逻辑，Tr = (N−1) × (T − Tcq − Tsu)，不计最后一级之后的余量。

```
[1] fclk = 500 MHz (T = 2.0 ns)；1 级时 Q 后面直接接 1.5 ns 组合逻辑
stages  Tr (ns)  Tr/tau  MTBF
     1     0.30    15.0  4.36 s (0.00121 h)
     2     1.80    90.0  5.16e+25 years
     3     3.60   180.0  6.3e+64 years
```

只有一级、后面还接了逻辑时，**平均 4 秒失效一次**；加第二级后 Tr 从 0.3 ns 变成 1.8 ns，MTBF 变成 10^25 年量级。这就是"打两拍"的由来。

```
[2] 提高目的时钟频率：两级 vs 三级
    fclk             2-stage MTBF             3-stage MTBF
  200MHz            1.8e+91 years          3.06e+195 years
  500MHz           5.16e+25 years            6.3e+64 years
 1000MHz           4.98e+03 years           1.17e+21 years
 2000MHz      1.09 s (0.000303 h)       3.56e+06 s (989 h)
 3000MHz               0.000175 s                  0.137 s
```

频率从 500 MHz 提到 2 GHz，两级同步器的 MTBF 从 10^25 年掉到 1 秒——因为 Tr 从 1.8 ns 缩到 0.3 ns。**高频下两级不够，要三级甚至更多**，或者降低同步器所在时钟的频率。

```
[3] 芯片里有 N 个同步器时，整体 MTBF = 单个 MTBF / N（1 GHz 两级）
  N=1       MTBF = 4.98e+03 years
  N=1000    MTBF = 4.98 years
  N=100000  MTBF = 1.57e+06 s (436 h)
```

单个同步器 5000 年听起来很安全，但芯片里有 1000 个就变成 5 年，再乘上出货量，现场失效就不可忽略了。

### 1.5 级数怎么选

| 情况 | 建议 |
|------|------|
| 一般控制信号、Gray 指针，中低频 | **2 级**（默认） |
| 高频（GHz 级）、同步器数量多、高可靠（车规、医疗） | 3 级，并按库的同步器 MTBF 数据核算 |
| 同步器之间 | **不放任何逻辑**，布局时靠近摆放 |
| 同步器单元 | 很多工艺库提供专门的同步器单元（τ 更小），并 `dont_touch` |

### 1.6 面试要点

- **亚稳态能不能消除**：不能，只能降低概率；同步器用时间换概率。
- **为什么两级就够**：第二级给第一级一个完整周期恢复，Tr 在指数上，MTBF 提升很多个数量级（本例从 4 秒到 10^25 年）。
- **什么时候用三级**：频率高、同步器多、可靠性要求高。
- **MTBF 公式各项含义**：Tr 在指数上最关键；fclk、fdata 在分母。
- **同步器第一级输出能不能直接用**：不能，可能亚稳，扇出后不同寄存器读到不同值。

**一句话**：亚稳态不可消除，MTBF = e^(Tr/τ) / (Tw·fclk·fdata)；多一级同步器 Tr 多一个周期，MTBF 按指数增长。

## 2. 单 bit 同步

### 2.1 解决什么问题，面试怎么考

一根单 bit **电平信号**（使能、模式、状态标志）从 A 域进入 B 域。最基本的 CDC 结构就是两级同步器（"打两拍"）。面试会让你手写，并追问：快到慢和慢到快有什么区别、电平至少要保持多久、两个相关的单 bit 分别同步有什么问题。

### 2.2 原理

```
 clk_src 域                 │              clk_dst 域
                           │
[FF_src]──── din ──────────┼───►[sync_q0]──►[sync_q1]──► dout ──► 本域逻辑
   ▲                       │       ▲            ▲
clk_src                    │    clk_dst      clk_dst
                           │   （可能亚稳）  （给恢复时间）
```

使用条件（缺一不可）：

1. **源信号直接来自源域寄存器**：中间不能有组合逻辑。组合逻辑输出会有毛刺，目的时钟可能恰好采到毛刺。
2. **电平保持足够长**：至少被目的时钟可靠采到一次。常用规则是保持 ≥ **1.5 个目的时钟周期**（Cummings 的"三个边沿"规则），这样无论相位如何，至少有一个目的上升沿落在稳定区。
3. **只用于单 bit**，或每次只变一位的多 bit（Gray 码，见第 4 节）。

慢→快：源信号自然保持很多个目的周期，直接两级同步即可。  
快→慢：源信号可能只保持一两个源周期，比目的周期还短，就会被漏采——要么保证源端保持足够长，要么改用脉冲同步或握手（第 3、4 节）。

延迟：dout 比 din 晚 STAGES 个目的时钟沿，再加上 0~1 个目的周期的相位不确定。真实芯片里第一级亚稳时可能落到新值也可能落到旧值，所以**同步延迟本身有 ±1 拍的不确定性**，下游逻辑不能依赖精确的跨域延迟。

### 2.3 RTL 讲解

`lab/Sync_2FF/sync_2ff.v`（参数化位宽和级数）：

```verilog
module sync_2ff #(
    parameter WIDTH  = 1,
    parameter STAGES = 2          // >= 2
)(
    input                  clk_dst,
    input                  rst_dst_n,
    input      [WIDTH-1:0] din,        // 来自源时钟域寄存器
    output     [WIDTH-1:0] dout
);
    reg [WIDTH-1:0] sync_q [0:STAGES-1];
    integer i;

    always @(posedge clk_dst or negedge rst_dst_n) begin
        if (!rst_dst_n) begin
            for (i = 0; i < STAGES; i = i + 1)
                sync_q[i] <= {WIDTH{1'b0}};
        end else begin
            sync_q[0] <= din;
            for (i = 1; i < STAGES; i = i + 1)
                sync_q[i] <= sync_q[i-1];
        end
    end

    assign dout = sync_q[STAGES-1];
endmodule
```

常见错误：

| 错误 | 后果 |
|------|------|
| 源端是组合逻辑输出（如 `assign flag = a & b` 直接跨域） | 毛刺被采到，产生虚假的电平变化 |
| 用 `sync_q[0]` 做逻辑 | 第一级可能亚稳 |
| 同步器级间插逻辑（如 `sync_q[1] <= sync_q[0] & en`） | 吃掉恢复时间，MTBF 下降 |
| 把 WIDTH > 1 的普通总线直接送进来 | 各 bit 落定时刻不同，采到新旧混合值（4.1 节实验） |
| 同步器用源时钟打拍 | 等于没有跨域——FIFO 早期代码就犯过这个错（`../03_Common_Circuits/lab/FIFO/README.md` 第 2 节） |

### 2.4 仿真

```bash
cd "06_CDC/lab/Sync_2FF"
bash run_sim.sh
```

`tb_sync_2ff.v` 三个场景，每个场景源端翻转 100 次，检查目的端看到的翻转次数和延迟（按顺序记录每次源端变化时的目的沿计数，逐次比对延迟是否恰好为 STAGES 个沿）：

```
----------------------------------------------------------
case                       src_toggles  dst_toggles  latency_err
A slow->fast 30ns->10ns          100          100            0
B fast->slow hold>=6 src         100          100            0
C fast->slow hold 1~3 src        100           24          -
----------------------------------------------------------
PASS
```

- A 慢→快：全部收到，延迟全是 2 个目的沿。
- B 快→慢（src 10 ns，dst 37 ns），电平保持 ≥ 60 ns（> 1.5 × 37 = 55.5 ns）：全部收到。
- C 同样的时钟，电平只保持 10~30 ns（短于一个目的周期）：**100 次变化只看到 24 次**。两次变化挨得太近时，目的端要么漏掉中间值，要么正反两次翻转互相抵消。

testbench 的一个细节：B 场景电平保持 60 ns，而两级同步要 2 × 37 = 74 ns 才能走完，所以同步器里可能同时有两次变化在路上。最初用单个计数器测延迟，结果报了 24 个假错误，改成按顺序排队记录后才正确。**这也说明：同步器是流水线，满足 1.5 周期规则时信号能被采到，但并不要求上一次变化已经走完。**

波形建议看：`u_c.clk_src`、`u_c.lvl_src`、`u_c.clk_dst`、`u_c.u_sync.sync_q[0]`、`u_c.lvl_dst`，能直接看到窄电平被漏掉。

### 2.5 变体与扩展

- **同步后做边沿检测**：dout 再打一拍，`dout & ~dout_d` 得到目的域的单周期脉冲——这就是慢→快脉冲同步的做法。
- **重汇聚（reconvergence）问题**：两个相关的单 bit 信号（比如 `mode[0]`、`mode[1]`）各自用同步器跨域，由于每个同步器的延迟有 ±1 拍不确定，它们可能在不同周期到达，目的端短暂看到一个从未出现过的组合。解决：在源端合成一个信号再跨域，或者当作多 bit 用握手/Gray 码处理。CDC 工具专门检查这一点。
- **准静态信号（quasi-static）**：上电配置一次后就不变的寄存器（如模式配置），跨域时有时只做 false path、不加同步器，靠"软件保证配置时目的逻辑没在工作"。这需要文档化的约定，CDC 工具里要标注为静态信号；不确定时还是加同步器。

### 2.6 面试要点与常见追问

- **手写两级同步器**：两个寄存器、目的时钟、级间无逻辑。
- **快到慢能不能直接打两拍**：只有电平保持 ≥ 1.5 个目的周期时可以；本实验 C 场景 100 次只收到 24 次。
- **慢到快呢**：可以，源信号自然足够宽。
- **同步延迟是多少**：约 2~3 个目的周期，且有 ±1 拍不确定性。
- **两个信号分别同步有什么问题**：重汇聚，可能在不同周期到达。

**一句话**：两级同步器只适用于"来自寄存器、保持 ≥ 1.5 个目的周期"的单 bit 电平；延迟 2~3 拍且不确定，相关的多个 bit 不能分别同步。

## 3. 脉冲同步

### 3.1 解决什么问题，面试怎么考

源域的单周期脉冲（"事件发生了一次"，如中断、计数、启动命令）要在目的域也变成**恰好一个**脉冲。快→慢时，源脉冲可能比目的周期还窄，直接打两拍会被漏采。这是高频手撕题："写一个快时钟域到慢时钟域的脉冲同步器"。

### 3.2 原理：toggle 型脉冲同步器

把"脉冲"变成"电平翻转"，电平可以慢慢跨域；到目的域再把"翻转"还原成脉冲。

```
 clk_src 域                               clk_dst 域
pulse_src ──►[toggle FF]── toggle ──►[s0]──►[s1]──►[s2]
              (来一次翻一次)                   │      │
                                              └─XOR──┘──► pulse_dst
                 ▲                              │
  busy = toggle ^ fb1                           │
                 │                              │
            [fb1]◄──[fb0]◄───────── s1 ─────────┘  （反馈：告诉源端已收到）
```

```
clk_src    _|‾|_|‾|_|‾|_|‾|_|‾|_|‾|_|‾|_|‾|_|‾|_|‾|_|‾|_|‾|_
pulse_src  __|‾‾|__________________________________________
toggle     _____|‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾   ← 电平，可以慢慢被采
clk_dst    ___|‾‾‾‾‾|_____|‾‾‾‾‾|_____|‾‾‾‾‾|_____|‾‾‾‾‾|____
s1         _________________________|‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾   ← 两级同步后
s2         _____________________________________|‾‾‾‾‾‾‾‾‾‾
pulse_dst  _________________________|‾‾‾‾‾‾‾‾‾‾‾|__________   ← s1 ^ s2：一个目的周期宽
busy       _____|‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾|__   ← s1 同步回源端后才撤销
```

**toggle 型的约束**：两个脉冲挨得太近，toggle 翻两次等于没翻，目的端一个都看不到。所以源端必须在 `busy = 0` 时才能发下一个脉冲。最小间隔约为：前向同步（2~3 个目的周期）+ 反馈同步（2~3 个源周期）。

### 3.3 RTL 讲解

`lab/Pulse_Sync/pulse_sync.v`：

```verilog
// 源域：来一个脉冲翻一次
always @(posedge clk_src or negedge rst_src_n)
    if (!rst_src_n)     toggle_src <= 1'b0;
    else if (pulse_src) toggle_src <= ~toggle_src;

// 目的域：两级同步 + 一级边沿检测
always @(posedge clk_dst or negedge rst_dst_n)
    if (!rst_dst_n) sync_dst <= 3'b000;
    else            sync_dst <= {sync_dst[1:0], toggle_src};

assign pulse_dst = sync_dst[2] ^ sync_dst[1];   // 用已同步的 [1][2]，不用 [0]

// 反馈：目的域第 2 级同步回源域
always @(posedge clk_src or negedge rst_src_n)
    if (!rst_src_n) fb_src <= 2'b00;
    else            fb_src <= {fb_src[0], sync_dst[1]};

assign busy = toggle_src ^ fb_src[1];
```

要点：

- 边沿检测用**异或**，因为 toggle 的上升和下降都代表一个脉冲。
- 边沿检测用 `sync_dst[1]` 和 `sync_dst[2]`，不能用 `sync_dst[0]`（可能亚稳）。
- `busy` 是闭环的关键：没有它就只能靠"源端保证脉冲间隔足够大"这种开环约定。

错误示范（`pulse_sync_naive`）：把源脉冲当电平直接打两拍再做上升沿检测——快→慢时脉冲可能落在两个目的沿之间，一个沿都没采到。

### 3.4 仿真


每个场景发 200 个单周期脉冲，同时送给 toggle 型和 naive 型，统计目的端输出的脉冲数：

```
----------------------------------------------------------
case                        pulses_in  toggle_out  naive_out  max_busy(src cyc)
A fast->slow 10->33, busy        200         200        170          8
B slow->fast 37->10, busy        200         200        200          2
C fast->slow, ignore busy        200         164         42          -
----------------------------------------------------------
PASS
```

- A 快→慢（10 ns → 33 ns），源端遵守 busy：toggle 型 200 个全部送达；naive 型丢了 30 个（10 ns 的脉冲落在 33 ns 周期的两个沿之间）。busy 最长持续 8 个源周期（80 ns ≈ 2~3 个目的周期 + 2 个源周期），这就是这对时钟下的最小脉冲间隔。
- B 慢→快（37 ns → 10 ns）：源脉冲宽 37 ns，远超 1.5 个目的周期，**naive 型也能 200/200**。慢→快时直接"两级同步 + 边沿检测"就够了。
- C 快→慢，无视 busy，脉冲间隔 1~4 个源周期：toggle 型也丢到 164 个（相邻两次翻转在目的端被抵消）；naive 型只剩 42 个（连续的脉冲被当成一段长电平）。

### 3.5 变体与扩展

| 方案 | 适用 | 特点 |
|------|------|------|
| 两级同步 + 边沿检测 | 慢→快，脉冲宽度 ≥ 1.5 个目的周期 | 最简单 |
| toggle 型（开环） | 快→慢，源端**保证**脉冲间隔足够大 | 无反馈，省逻辑 |
| toggle 型 + busy 反馈（本实验） | 快→慢，间隔不可控 | 闭环，源端知道何时能发 |
| 四相握手脉冲同步 | 同上 | req/ack 电平，更直观但更慢（见 4.3 节） |
| 脉冲太密（每几个周期一个） | 任何方向 | 同步器跟不上，改用**计数**跨域（Gray 码计数器）或异步 FIFO |

### 3.6 面试要点与常见追问

- **手写快到慢脉冲同步**：源端 toggle、目的端两级同步 + 异或边沿检测；加分项是 busy 反馈。
- **为什么不能直接打两拍**：窄脉冲可能落在两个目的沿之间（本实验丢了 30/200）。
- **两个脉冲间隔的要求**：约 2~3 个目的周期 + 2~3 个源周期；不满足会抵消（本实验 C 场景）。
- **慢到快怎么同步脉冲**：两级同步 + 边沿检测即可（B 场景 naive 也 200/200）。
- **脉冲很密怎么办**：不要逐个同步，传计数值（Gray 码）或用异步 FIFO。

**一句话**：快→慢脉冲同步 = 源端把脉冲转成 toggle 电平，目的端两级同步后异或还原；两次脉冲之间必须留够往返时间，用 busy 反馈保证。

## 4. 多 bit 同步

### 4.1 为什么多 bit 不能直接打两拍（实验）

直觉上"每一位都打两拍"似乎没问题，但**各 bit 的走线延时不同**（布线长度、负载不同），源端同时变化的几个 bit 到达同步器的时刻有先后。目的时钟沿如果落在这段偏斜窗口里，就会采到"一部分 bit 已是新值、一部分还是旧值"的组合。即使完全没有亚稳态，这也会发生；亚稳态只会让情况更糟。

`lab/Sync_2FF/tb_bus_skew.v`：源域 4 bit 计数器每 10 ns 加 1，bit i 的走线延时为 0.4 + 0.8i ns（最大偏斜 2.4 ns），目的时钟 13 ns，分别同步二进制总线和 Gray 码总线。检查第一级每次采到的值解码后是否是"旧值或新值"：

```
  t= 136.87  old=1011 new=1100  binary sync captured=1000  <- 非法值
  t= 175.87  old=1111 new=0000  binary sync captured=1110  <- 非法值
  t= 435.87  old=1001 new=1010  binary sync captured=1000  <- 非法值
----------------------------------------------------------
samples=2000  binary incoherent=150  gray incoherent=0
----------------------------------------------------------
PASS
```

以第一行为例：135 ns 源端从 1011 变到 1100，bit0、bit1 分别在 135.4、136.2 ns 到达新值，bit2 要到 137.0 ns；目的沿在 136.87 ns，采到 bit3..0 = 1、0（bit2 还是旧值）、0、0 = **1000**——既不是 11 也不是 12，是 8。

- 二进制：2000 次采样有 150 次是非法值（7.5%）。
- Gray 码：相邻值只差 1 bit，混合态只能是旧值或新值之一，**0 次**非法值。

所以 Gray 码能直接用多 bit 同步器跨域，**前提**是：

1. 源端每个源周期最多变化一步（+1 或 −1），即计数器/指针；
2. 各 bit 之间的走线偏斜小于一个源周期——这要靠约束保证（第 5.3 节的 `set_max_delay -datapath_only`）；
3. 计数范围是 2 的幂（或专门设计的循环 Gray 码），回绕时也只变 1 bit。

### 4.2 方案选择

| 数据特征 | 方案 | 吞吐 | 说明 |
|----------|------|------|------|
| 计数器、指针（每次 ±1） | Gray 码 + 多 bit 同步器 | 每个目的周期一次（可跳值） | 异步 FIFO 的指针就是这样 |
| 任意数据，偶尔传一次 | 四相握手（4.3 节） | 低 | 最稳妥、最容易讲清楚 |
| 任意数据，较频繁 | 两相 MCP（4.4 节） | 约为四相的 2 倍 | 数据保持、只同步一个使能 |
| 连续数据流、突发 | 异步 FIFO（4.6 节） | 每周期一个 | 面积最大 |
| 上电配置后不变 | 准静态，false path | — | 需要软件时序约定 |

### 4.3 四相握手

```
src:  锁存数据，req=1 ────────────────►  dst: 看到 req=1（同步后），采数据，ack=1
src:  看到 ack=1（同步后），req=0 ────►  dst: 看到 req=0，ack=0
src:  看到 ack=0 → 空闲，可发下一笔
```

```
clk_src  ‾|_|‾|_|‾|_|‾|_|‾|_|‾|_|‾|_|‾|_|‾|_|‾|_|‾|_|‾|_|‾|_|‾|_|‾|_
data     ══X═══════════ D0 保持不变 ═══════════════════════X═══ D1
req      __|‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾|_________________________|‾‾‾‾
ack      _____________|‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾|______________
                      ↑ dst 在这里采 data            ↑ src 看到 ack=0 才空闲
```

为什么数据总线不需要同步器：数据在 req 拉高**之前**就已锁存，并一直保持到 ack 回来；目的端看到同步后的 req 时，数据已经稳定了至少两个目的周期，直接采样是安全的。**只有 req 和 ack 两根单 bit 线过同步器**。

`lab/Multi_Bit_Sync/handshake_sync.v` 关键代码：

```verilog
// 源域
assign src_ready = !req && !ack_s;     // 上一轮彻底结束（ack 也回到 0）才空闲

always @(posedge clk_src or negedge rst_src_n)
    if (!rst_src_n) begin
        req <= 1'b0; data_hold <= {W{1'b0}};
    end else if (src_valid && src_ready) begin
        req <= 1'b1; data_hold <= src_data;      // 数据和 req 同时锁存
    end else if (req && ack_s) begin
        req <= 1'b0;
    end

// 目的域
req_sync  <= {req_sync[0], req};
req_d     <= req_s;
ack       <= req_s;                     // ack 跟随同步后的 req
dst_valid <= req_s && !req_d;           // req 上升沿：数据有效一拍
if (req_s && !req_d) dst_data <= data_hold;
```

常见错误：

- `src_ready` 只看 `!req`，不等 ack 回到 0 → 下一轮 req 拉高时目的端还没看到上一轮的 req 下降，上升沿检测不到，数据丢失。
- 在 req 为高期间改变 data_hold → 目的端采到不稳定的数据。
- 目的端用 `req_sync[0]` 采数据。

### 4.4 两相 MCP 同步

四相握手每笔要往返两次（req↑ack↑、req↓ack↓）。两相（toggle）握手用"翻转"代替"电平"，每笔只往返一次。Cummings 把"数据保持不动、只同步一个加载使能"的结构叫 **MCP formulation**（Multi-Cycle Path）：数据路径不同步，但保证它在被采样前已经稳定了多个周期。

`lab/Multi_Bit_Sync/mcp_sync.v` 关键代码：

```verilog
// 源域：req_tog 与同步回来的 ack_tog 相等 → 上一笔已被收下
assign src_ready = (req_tog == ack_sync[1]);
always @(posedge clk_src ...)
    else if (src_valid && src_ready) begin
        req_tog   <= ~req_tog;
        data_hold <= src_data;
    end

// 目的域：toggle 同步 + 异或边沿检测 → load
wire load = req_sync[2] ^ req_sync[1];
always @(posedge clk_dst ...)
    req_sync  <= {req_sync[1:0], req_tog};
    dst_valid <= load;
    if (load) begin
        dst_data <= data_hold;          // 多周期路径：此时 data_hold 已稳定
        ack_tog  <= ~ack_tog;
    end
```

它其实就是第 3 节的 toggle 脉冲同步器，外加一组随脉冲一起"搭车"的数据。

```
----------------------------------------------------------

4-phase handshake 10 -> 27 ns      300/300     0    180.3      18.0         6.7
```

### 4.6 异步 FIFO

连续数据流跨域的标准答案。完整代码、testbench 和讲解见 `../03_Common_Circuits/lab/FIFO/README.md`。和本章相关的要点：

- 读写指针用 **Gray 码**跨域（4.1 节的前提全部满足：每次 +1、深度是 2 的幂）；
- 每个方向一个多 bit 两级同步器（`../03_Common_Circuits/lab/FIFO/FIFO.v` 的 `synchronization` 模块）；
- 同步带来的延迟让 full/empty **偏保守**（虚满、虚空），用少量吞吐换正确性；
- 数据本身存在双口 RAM 里，不过同步器——和握手一样，靠"控制信号同步、数据保持稳定"。

### 4.7 面试要点与常见追问

- **多 bit 为什么不能直接打两拍**：bit 间偏斜 → 采到新旧混合的非法值（本实验 7.5% 的采样非法）。
- **Gray 码为什么可以**：相邻值只差 1 bit，最坏也只是旧值或新值；前提是每次只变一步、偏斜受约束。
- **握手和 MCP 的区别**：四相 req/ack 电平往返两次；两相 toggle 往返一次，吞吐约高一倍（本实验 180 ns vs 90 ns）。
- **握手里数据线为什么不用同步**：数据先锁存、在 req/ack 往返期间保持不变，采样时早已稳定。
- **什么时候用异步 FIFO**：连续数据流、需要每周期一笔的吞吐。

**一句话**：多 bit 跨域的核心是"只同步单 bit 控制信号，数据在采样时保持稳定"；计数器用 Gray 码，偶发数据用握手/MCP，数据流用异步 FIFO。

## 5. CDC 检查与约束

### 5.1 为什么仿真和 STA 都不够

- **RTL 仿真没有亚稳态**：本章所有 testbench 里，同步器的延迟都是确定的。仿真只能验证协议逻辑（握手顺序、busy 约束），验证不了同步器本身是否"够"。
- **STA 不分析异步路径**：跨域路径被 `set_clock_groups -asynchronous` 排除，STA 结果对它们没有意义（`../07_STA/README.md` 第 11 节、lab 实验 2）。
- 所以需要**静态 CDC 检查工具**：在结构上找出所有跨域路径，确认每一条都有正确的同步方案。

### 5.2 CDC 工具查什么

常见工具：Synopsys SpyGlass CDC / VC SpyGlass、Siemens Questa CDC、Cadence Conformal CDC / JasperGold CDC、Real Intent Meridian CDC。规则名称各家不同，以工具文档为准；检查的内容大致如下：

| 类别 | 检查内容 | 对应本章 |
|------|----------|----------|
| 设置 | 时钟、复位定义是否完整；哪些时钟互为异步 | SDC 里的 clock groups |
| 未同步的跨域 | 跨域信号没有经过任何可识别的同步器 | 第 2 节 |
| 同步器前的组合逻辑 | 源端不是寄存器直接输出，可能有毛刺 | 2.2 节条件 1 |
| 多 bit 直接同步 | 多个 bit 各自用同步器跨域，且不是 Gray 码 | 4.1 节 |
| 重汇聚（reconvergence） | 分别同步的信号在目的域又汇合 | 2.5 节 |
| 快→慢脉冲丢失 | 源信号宽度可能小于目的周期 | 3.4 节 |
| 数据保持 | 握手/MCP 方案中，数据在使能有效期间是否稳定（常用形式化验证） | 4.3、4.4 节 |
| 复位 | 异步复位是否同步释放；RDC | `../05_Clock_Reset_Design/README.md` 第 5 节 |

典型流程：先做**结构检查**（识别同步器、找违规），再对握手、Gray 码等协议做**功能检查**（形式化证明"Gray 码每次只变 1 bit"、"数据在 req 期间不变"），最后对剩余告警逐条评审（waive 要写理由）。部分工具还支持在仿真中注入亚稳态（随机让同步器多/少一拍），用来发现依赖精确同步延迟的逻辑。

设计上配合工具的习惯：

- 同步器写成独立模块并统一命名（如 `sync_2ff`、`pulse_sync`），工具可以按模块名识别；
- 综合时对同步器 `dont_touch`，避免被优化或和别的逻辑合并；
- FPGA 上 Xilinx 用 `ASYNC_REG` 属性标注同步器寄存器，让工具把它们放在一起并计算 MTBF。

### 5.3 SDC 约束写法

跨域路径在 STA 里的处理（命令语义见 `../07_STA/README.md` 第 8 节）：

```tcl
# 1. 声明异步时钟组：跨域路径不做 setup/hold 分析
set_clock_groups -asynchronous -group [get_clocks clk_src] -group [get_clocks clk_dst]

# 2. Gray 码指针 / 多 bit 同步器：不做完全的 false path，而是限制数据路径延时，
#    保证各 bit 之间的偏斜小于一个源周期（4.1 节的前提 2）
#    -datapath_only 在 PrimeTime 中可用，其它工具以文档为准
set_max_delay 10.0 -datapath_only \
    -from [get_cells u_fifo/w_gray_reg*] -to [get_cells u_fifo/sync_w2r/sync_q0_reg*]

# 3. MCP / 握手的数据路径：数据保持多个周期，同样限制最大延时即可
set_max_delay 20.0 -datapath_only \
    -from [get_cells u_mcp/data_hold_reg*] -to [get_cells u_mcp/dst_data_reg*]
```

- 用了 `set_clock_groups -asynchronous` 后，某些工具中 `set_max_delay` 的优先级关系要确认（例外的优先级见 `../07_STA/README.md` 第 8.6 节）；常见做法是不声明 clock groups，改为对每组跨域路径分别写 `set_max_delay -datapath_only` 或 `set_false_path`。具体以团队的约束规范和工具文档为准。
- 单 bit 电平同步器（第一级 D 端）通常可以直接 false path，因为只有一根线，不存在 bit 间偏斜。
- 本章 lab 没有跑这些 SDC（开源 OpenSTA 与 PrimeTime 在 `-datapath_only` 等选项上不完全一致），上面是写法示例。

### 5.4 面试要点与常见追问

- **CDC 问题能靠仿真发现吗**：基本不能，RTL 仿真没有亚稳态；要靠结构（同步器）+ CDC 静态检查。
- **STA 怎么处理跨域路径**：clock groups / false path 排除；Gray 码和 MCP 数据路径用 `set_max_delay -datapath_only` 限制偏斜。
- **CDC 工具常见告警有哪些**：未同步、同步器前有组合逻辑、多 bit 分别同步、重汇聚、脉冲丢失。
- **为什么 Gray 指针不能直接 false path**：false path 让工具完全不管这些线的延时，布线后 bit 间偏斜可能超过一个周期，破坏"一次只变一位"。

**一句话**：CDC 正确性靠设计结构 + 静态 CDC 工具，不靠仿真和 STA；SDC 里异步路径要排除，但 Gray/MCP 数据路径要用 max delay 限制偏斜。

- 把 `tb_bus_skew.v` 的偏斜改成 `0.4 + 4.0*g`（最大 12.4 ns，超过 10 ns 的源周期），并让检查也接受 `cnt - 2`（延时超过一个周期后，旧两拍的值也是合法的旧值）。实测 Gray 码 2000 次采样出现 50 次非法值——验证"偏斜必须小于一个源周期"，也就是 5.3 节要用 `set_max_delay` 约束的原因。
- 把 `pulse_sync.v` 的边沿检测改成 `sync_dst[1] ^ sync_dst[0]`，想一想为什么仿真结果不变，但真实电路有风险。
- 在 `handshake_sync.v` 里把 `src_ready` 改成只看 `!req`。实测第 2 笔起目的端就收到错误数据，记分板等不到 300 笔、仿真卡住——req 的低电平太短，目的端没看到它下降，上升沿检测失效。

## 7. 速查表

```
亚稳态：不可消除，只能降低概率；第一级输出不能扇出
MTBF = e^(Tr/τ) / (Tw · fclk · fdata)；Tr 在指数上，多一级 ≈ 多一个周期
级数：默认 2 级；GHz 级、同步器多、高可靠 → 3 级；级间不放逻辑
整体 MTBF = 单个 / 同步器数量

单 bit 电平：两级同步器；源端必须是寄存器；保持 ≥ 1.5 个目的周期
  延迟 2~3 个目的周期，±1 拍不确定；相关的多个 bit 不要分别同步（重汇聚）
脉冲：慢→快 两级同步 + 边沿检测；快→慢 toggle + 两级同步 + 异或，busy 反馈控制间隔
多 bit：
  计数器/指针 → Gray 码 + 多 bit 同步器（每次只变 1 步、偏斜 < 1 源周期）
  偶发数据   → 四相握手（往返两次）/ 两相 MCP（往返一次，吞吐 ×2）
  数据流     → 异步 FIFO
  配置寄存器 → 准静态 + false path（需软件约定）
CDC 检查：静态工具（SpyGlass / Questa / Conformal / Meridian CDC），RTL 仿真没有亚稳态
SDC：set_clock_groups -asynchronous；Gray / MCP 数据路径 set_max_delay -datapath_only
```
