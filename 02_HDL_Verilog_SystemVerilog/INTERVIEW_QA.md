# 第 02 章面试问答

- 这里的 44 题用来检查 [README](README.md) 中的概念是否真的理解了，不要求第一次就答全。遇到代码题，先在纸上标出每个信号几位、按什么符号解释；遇到时序题，分开写“沿前旧值”和“沿后新值”。这样能从电路行为推出答案，不必只背规则。

## 概念与找错

**1. wire 与 reg 有什么区别？reg 一定产生触发器吗？**

- 先看赋值在哪里发生：wire 常用来连接连续赋值或模块输出，reg 用于过程赋值。

- 再看过程何时更新：若相关输入一变就重算且每条路径都赋值，描述的是组合逻辑；若只在时钟沿更新，描述的是触发器；若组合过程中某些条件没有赋值，却要求保留旧值，就可能推断 latch。因而不能只看 reg 这个名字判断硬件。

**2. assign 与 always 是顺序执行的吗？**

- 不同连续赋值和过程并发，不能靠源码前后来规定先后。同一过程内语句有顺序，但 NBA 把目标更新推迟，所以还要区分“语句执行”和“变量更新”。

**3. 把信号写错一个字母，为什么不一定立即报错？**

- 某些上下文允许自动建立没有显式声明的线网，拼错的名字可能因此变成另一根 1 位 wire。`default_nettype none` 要求先声明再使用，能让这类错误更早报出。

- Lint 是不运行测试激励的静态代码检查，会寻找可疑位宽、未使用信号、多驱动等问题；它帮助找错，但不能代替功能仿真。

**4. `$signed(a)` 会给无符号数多加一位吗？**

- 不会。8 位 `8'hff` 转 signed 是 −1，不是 +255；如果要保留其无符号数值，在前面补 0 再转 signed。

**5. signed 向量取全部位还是 signed 吗？**

- 例如 `reg signed [7:0] s` 的 `s[7:0]` 是 unsigned 切片。`s` 与 `s[7:0]` 的位完全相同，但扩展、比较时可能不同。

**6. `>>>` 一定补符号位吗？**

- 只有左操作数具有 signed 解释时才算术补符号。检查切片、拼接、类型传播是否把它变为 unsigned。

**7. 组合逻辑为什么用阻塞赋值？**

- 后面的中间计算需要看到本次算出的值；NBA 会把更新推迟，导致额外调度或旧值依赖。使用 `always @*` 并保证输出覆盖所有路径。always_comb 的额外语义见 README 第 6 节。

**8. `q1<=d; q2<=q1;` 中 q2 读到哪个 q1？**

- 读到执行语句时的旧 q1。比如沿前 q1=3、d=5，第一条语句预约把 q1 更新成 5，第二条仍读到 3，于是预约把 q2 更新成 3；统一更新后得到 q1=5、q2=3。RHS 指等号右边，NBA 指非阻塞赋值更新区。

**9. 时序 always 里没有 else 会生成 latch 吗？**

- 没有使能时保持原状态，这是触发器使能行为。组合过程遗漏赋值才是常见意外 latch 来源。不能仅凭“缺 else”下结论。

**10. 连写 `q<=0; if(en) q<=d;` 一定多驱动吗？**

- 同一过程内有明确执行顺序，en 为真时后一次赋值生效，否则 q 清零。它不是“默认保持”：默认保持应不赋值或明确写 q。两个不同过程写同一状态是另一类问题。

**11. 全部使用 `<=` 就不会竞争吗？**

- 不会。TB 同沿阻塞驱动、多个过程写同一状态、错误采样区域都可能造成竞争。正确做法包括单写者和明确的驱动/采样时机。

**12. `$display`、`$strobe`、`$monitor` 如何选择？**

- display 在执行语句时打印；strobe 在当前时间片末观察最终值；monitor 在监视参数变化时于时间片末报告。打印旧值不一定是 DUT 错，要看观察区域。

**13. 为什么 `#0` 不能等待 NBA 完成？**

- module 中的 #0 将过程移到 Inactive，仍早于当前的 NBA 更新。零延迟 RTL TB 可在合理的小延迟后或下一相反沿检查；专业验证还可用 clocking block 等方法。

**14. `if (actual != expected)` 有什么验证风险？**

- 有未知位时 `!=` 可能返回 X，if 不进入真分支，漏报。精确匹配使用 `!==`；泛化条件可以用 `condition !== 1'b1`。若允许部分位未知，需先明确掩码策略。

**15. 仿真中 x 是亚稳态吗？**

- 不是。x 是离散未知值，不能提供模拟电压、恢复时间或概率。CDC 和时序约束要另外验证。

**16. 负数算术右移和除以 2 相同吗？**

- 负奇数不同：−3>>>1 为 −2，整数 −3/2 为 −1。前者向负无穷取整，后者向零截断。

**17. 如何证明本章实验不是只打印一个 PASS？**

- Expressions 每个输入对用整数参考模型检查六项，额外检查已知位宽与 X 探针；Scheduling 比较旧状态、更新后状态、停顿、复位和反例，失败 `$fatal` 返回非零。

- 脚本还 lint 并检查综合结构。仍不等于穷举所有时间序列。

## 手算题

**18. 8 位 x=255、y=1，`wire [8:0] s=x+y` 与 `wire [8:0] t={x+y}` 是多少？**

- s=`9'h100`，赋值上下文影响加法位宽；t=`9'h000`，拼接内部按 8 位算完后已丢进位。推荐 `{1'b0,x}+{1'b0,y}` 显式扩展。

**19. signed 8 位 s=−1，unsigned 8 位 u=1，`s<u` 为何是假？**

- 混合符号按 unsigned 比较，ff 是 255。保留两者本来的数值含义，使用 `$signed({s[7],s}) < $signed({1'b0,u})`，结果为真。

- 这里选择九位是因为九位 signed 能同时容纳 −128..127 和 0..255。s 复制符号位后仍表示 −1，u 前面补 0 后仍表示 +1，再将两边都按 signed 比较。

- 直接给八位 u 加 `$signed`，则会把本来合法的 128..255 误解释成负数。

**20. 4 位 signed 7+1 与 −1+1，哪一个溢出？**

- 7+1 完整和是 5 位 `01000`，截到 4 位为 `1000`（−8），溢出。−1+1 为 0，无 signed 溢出；把同一位模式当 unsigned 时 15+1 会有进位。

**21. q1=q2=0，连续三个沿 d=3、5、9，en=1、0、1，NBA 流水线沿后是什么？**

- 第一个沿使能为 1，q1 收到 3，q2 收到旧 q1=0，得到 `(3,0)`。第二个沿使能为 0，即使 d 变成 5，两级都不更新，仍是 `(3,0)`。

- 第三个沿使能恢复，q1 收到 9，q2 收到旧的 3，得到 `(9,3)`。关键是先保存旧状态，再同时计算两个新状态。

**22. 15 ns 上升沿前 q=0、d=1，DUT 执行 `q<=d`；观察进程在该沿 display、#0 后 display、strobe 分别看到什么？**

- 本题只有 DUT 写 q，d 提前稳定：依次 0、0、1，时间都为 15 ns。若 TB 同沿也写 d，题目增加了 race，不能再直接套这个唯一答案。

**23. 条件 c=x，两分支为 1010 与 1000，条件表达式和 if/else 的输出？**

- `c ? 1010 : 1000` 按位合并为 10x0；if 的未知条件不视为真，因此选 else=1000。指出 if 的 X 乐观风险，而不是说实际芯片一定选 else。

**24. 初始 d=1，2 ns 时改为 0，0 ns 启动 `q<=#5 d`，5 ns 后 q 是多少？**

- 1，RHS 在 0 ns 已读取。若是 `#5 q=d`，到 5 ns 才读取 d，得到 0。两种都是仿真时序描述，不作为可综合延迟电路。

## 可综合风格与参数化

**25. 固定十次的组合 for 循环要跑十拍吗？**

- 不。其算法在同次组合求值中完成，综合可以展开为固定电路；若要十拍执行，需要寄存器、计数器和状态转移明确描述跨拍行为。展开后的面积和路径深度需要检查。

**26. 三段式状态机的第三段一定是输出寄存器吗？**

- 不。本章第三段是从当前状态译码的组合输出；也有注册输出风格。段数是代码组织，不等于拍数，必须看敏感条件与赋值对象。

**27. IDLE 时 req、finish、ack 都为 1，本章 FSM 一个沿能完成事务吗？**

- 不能。本沿按旧 state=IDLE 计算转移，只进入 WORK。finish 需在 WORK 的采样沿有效，ack 需在 RESP 的采样沿有效。提前信号不能使一个沿跨越三个状态。

**28. 给状态机加 default 返回 IDLE，能保证流片后非法状态安全恢复吗？**

- 不能。它给出 RTL 行为，综合可能重编码、优化不可达状态；安全设计要明确故障模型并检查实现后恢复行为。本章未做故障注入。

**29. parameter、localparam、输入配置寄存器有何区别？**

- 前两者在展开时决定常量，parameter 可由实例覆盖，localparam 用于内部派生；运行时配置寄存器有真实存储，并通过逻辑影响运行行为。generate 不能依赖运行时输入选择结构。

**30. N=1/3/8 时选择位宽是多少？为何还要检查值域？**

- 本例用 max(1,clog2(N))，分别 1/2/3 位；N=1 的编码 1 非法，N=3 的编码 3 非法，N=8 全部合法。位宽只是表示能力。

**31. 深度 8 的 FIFO 地址和占用计数各几位？深度 3 呢？**

- 先分别数要表示多少种情况。深度 8 有地址 0..7，共八种，三位够用；占用量还包括“一个都没有”和“八个全满”，即 0..8 共九种，要四位。

- 深度 3 时地址是 0..2，占用是 0..3，都用两位，但地址编码 3 没有对应存储位置。位宽相同不表示合法范围相同。

**32. param_mux 的 W=8、N=3、PIPE=1 有多少数据寄存位？sel 变化要等一拍吗？**

- 24 位数据存储（Yosys 中是三个 8 位 `$adff` 单元），sel 未寄存，因此在沿间改变 sel 会组合地选择另一份已保存数据。它不是将 MUX 输出简单延迟一拍的同义写法。

**33. generate-for 与过程 for 的差别？**

- generate-for 在展开阶段复制层次、实例、声明；过程 for 描述过程算法，固定边界综合后也可展开硬件，但不能在过程里实例化模块。两者都不自动增加时钟周期。

## SystemVerilog 设计

**34. logic 能替代所有 wire 吗？**

- 不能简单如此理解。logic 是四态元素类型，普通变量适合单驱动，net 才提供需要的驱动解析语义。inout/多驱动场景仍需合适的线网类型；logic 也不承诺生成哪种器件。

**35. always_comb 比 always @* 多什么？能自动修 latch 吗？**

- 有启动时执行、扩展敏感推导、写者约束等语义，表达组合意图；不会替你补齐缺失赋值。先读后写仍要遵守过程顺序，不应依赖自触发迭代。

**36. always_ff 的单事件控制禁止异步复位吗？**

- 不。`@(posedge clk or negedge rst_n)` 是一个事件控制，包含时钟和异步复位事件。关键是单一状态写者、合法过程结构及明确寄存器行为，不是简单地数敏感表达式中的信号个数。

**37. 请求 packed struct 的 2 位 op、8 位 a、8 位 b 一共多少位？谁在高位？**

- 18 位，先声明的 op 位于最高的 [17:16]，a 在 [15:8]，b 在 [7:0]。这是位布局，不自动给出外部总线的字节序约定。

**38. enum 的强制转换能证明值合法吗？**

- 不能。转换规定类型解释，协议合法性要另查。本例把所有两位编码命名，其中 OP_BAD=3 明确输出 error；即使只命名三个值，也不能假设外部线路永远不出现第四种编码。

**39. package 与 interface 的差别？**

- Package 像共同使用的类型和常量说明书，例如统一规定请求含哪些字段；它本身不实例化成电路。Interface 则把一组实际连接信号集中起来，例如请求、响应及 valid/ready。

- Modport 再规定连接者读取或驱动哪些信号。这些机制帮助组织代码，握手和跨时钟传输仍需自行设计。

**40. 单槽响应满且下游不 ready 时能更新 result 吗？**

- 不能，valid=1 且未握手意味着同一响应仍待消费，其 payload 必须保持。只有空槽或旧响应将被消费时才能接受替换；本例 `req_ready=!rsp_valid || rsp_ready`。

- payload 就是这笔响应携带的内容，本例包括结果与错误标志。若 valid 一直为 1 却把结果从 8 换成 10，下游恢复 ready 时会拿到 10，原来的 8 就丢了；因此保持义务不只是保持 valid 这一根线。

## 常见陷阱与工具

**41. `always @(a) y=a&b` 为什么前仿真可能不同于网表？**

- 标准事件仿真漏掉 b 变化触发，综合仍建立依赖 a、b 的 AND。保持 a=1、只把 b 从 0 改 1，本章实测 RTL=0、生成网表=1。用 @* 或 always_comb 修复。

**42. casez 是否不会掩盖未知输入？**

- 它不把 X 全部作为通配，但会把选择信号中的 Z 当通配。本章 z1 对 1? 匹配导致高位授权；casex 还会吞 X。是否允许通配要由已知输入约束和协议决定。

**43. 两个时钟各写 q，能得到“双时钟寄存器”吗？**

- 不能据此推导合法器件。本章综合后检查出两个冲突驱动。需要先明确时钟域、数据传输和状态归属，不能靠换赋值符号或关闭告警解决。

**44. 本章六组实验通过，能得出哪些结论，不能得出哪些？**

- 给定配置与激励下行为符合参考模型，指定的结构条件成立，错误样例被预期检测到。

- 不能证明所有参数/时间序列正确、SV 跨工具综合可移植或时序签核通过；SV 实验是二态仿真，X/Z 与敏感列表实验由 Icarus 单独完成。
