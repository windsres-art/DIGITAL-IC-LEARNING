## 1. 时钟产生与 PLL

### 1.1 时钟从哪里来

| 时钟源 | 特点 | 典型用途 |
|--------|------|----------|
| 晶体振荡器（crystal oscillator，XO） | 频率准（ppm 级）、频率不高（几 MHz 到几十 MHz） | PLL 的参考时钟 |
| 片上 RC 振荡器 | 不准（百分之几），但不需要外部器件、上电即起振 | 上电启动、低功耗待机、看门狗 |
| 外部时钟引脚 | 由板上其它芯片提供 | 接口随路时钟（如 RGMII、DDR 的 DQS） |
| **PLL（锁相环）** | 把低频参考时钟倍频成高频，并锁定相位 | 核心、总线、接口的主时钟 |

芯片里的高频时钟几乎都来自 PLL：外部晶振给 25 MHz，PLL 倍频到 1 GHz，再经分频器、时钟 MUX、门控单元分给各个时钟域。

### 1.2 PLL 基本原理

PLL（Phase-Locked Loop）是一个负反馈环：比较参考时钟与反馈时钟的相位，调节压控振荡器（VCO）的频率，直到两者相位对齐（锁定）。

```
          ┌──────┐   up/dn  ┌────┐  电流  ┌─────┐  电压  ┌─────┐
fref ──►÷M│ PFD  ├─────────►│ CP ├───────►│ LPF ├───────►│ VCO ├──┬──►÷P──► fout
          └──▲───┘          └────┘        └─────┘        └─────┘  │
             │                                                     │
             └───────────────────── ÷N ◄───────────────────────────┘
                                   反馈分频
```

| 模块 | 作用 |
|------|------|
| PFD（鉴频鉴相器） | 比较 fref/M 与 fvco/N 的相位差，输出 up/down 脉冲 |
| CP（电荷泵） | 把 up/down 脉冲转成充/放电电流 |
| LPF（环路滤波器） | 把电流积分成平滑的控制电压，决定环路带宽和稳定性 |
| VCO（压控振荡器） | 电压越高频率越高 |
| ÷N 反馈分频 | 锁定时 fref/M = fvco/N，所以 **fvco = fref × N / M** |
| ÷P 输出分频 | fout = fvco / P，让 VCO 工作在它最稳定的频率范围 |

例：fref = 25 MHz，M = 1，N = 40 → fvco = 1 GHz；P = 2 → fout = 500 MHz。

面试常追问的几个点：

- **锁定（lock）**：上电或改配置后，PLL 要经过一段锁定时间（通常微秒级）才稳定。PLL 通常输出 `lock` 信号，**时钟未锁定前，下游逻辑要保持复位**，或先用旁路时钟（bypass，直接用参考时钟）。这是复位控制器的常见逻辑。
- **jitter 来源**：VCO 自身噪声、电源噪声、参考时钟抖动。环路带宽大，跟踪参考时钟快，但会把参考时钟的抖动传过来；带宽小则 VCO 自身噪声滤除得少。jitter 在 STA 里体现为 clock uncertainty（见 `../07_STA/README.md` 第 5.4 节）。
- **DLL（延迟锁相环）**：用可调延迟线代替 VCO，只对齐相位、不产生新频率，常用于接口去偏斜（deskew），例如 DDR。
- **展频时钟（SSC，Spread Spectrum Clocking）**：让频率在小范围内缓慢调制，降低 EMI 峰值；代价是 STA 要按最短周期计算。
- 数字前端工程师一般不设计 PLL（那是模拟/混合信号团队的活），但要会**集成**：配置寄存器、锁定等待、切换到 PLL 时钟（见第 3 节）、为 PLL 输出写 `create_clock` / `create_generated_clock`。

### 1.3 时钟树概念

PLL 输出一个时钟，但要驱动成千上万个触发器。不能用一根线直接拉过去：负载太大，边沿会很慢，而且到达各触发器的时间差异巨大。

```
PLL ──► 时钟 MUX ──► 分频器 ──► ICG ──►[buf]──┬──►[buf]──┬──► FF
                                              │          └──► FF
                                              └──►[buf]──┬──► FF
                                                         └──► FF
                                  └───── 时钟树（由 CTS 在后端自动构建）─────┘
```

- **时钟树综合（CTS，Clock Tree Synthesis）**：后端工具插入 buffer/inverter 树，目标是控制 **skew**（到达各寄存器的时间差）、**latency**（插入延时）和 **transition**（边沿斜率）。常见拓扑有 H-tree、时钟网格（mesh）、多源 CTS。详见第 14 章。
- 前端要做的是**让时钟结构简单、可分析**：时钟只从端口或 PLL、分频器、ICG、时钟 MUX 这些明确的点出来，不要让时钟经过普通组合逻辑。

### 1.4 RTL 里对时钟的规矩

| 规矩 | 原因 |
|------|------|
| 时钟不进普通组合逻辑（不要写 `assign clk2 = clk & a`） | 组合逻辑会产生毛刺，STA 也很难为它定义时钟 |
| 能用**时钟使能**（clock enable）就不要造新时钟 | 使能只是 D 端的 MUX，整个设计仍是一个时钟域；分频出来的新时钟需要额外 CTS、`create_generated_clock`，还可能形成跨域 |
| 必须分频时，分频时钟从寄存器 Q 端直接输出 | 寄存器输出无毛刺；并在 SDC 里写 `create_generated_clock -divide_by N` |
| 门控用 ICG 单元（第 2 节）、切换用专用结构（第 3 节） | AND/MUX 直接处理时钟会出毛刺 |
| 时钟相关单元加 `dont_touch`，或直接例化库单元 | 防止综合工具把它们优化、重构掉 |

分频器电路本身见第 03 章第 5 节"时钟分频"（`../03_Common_Circuits/README.md`）。

### 1.5 面试要点

- 问"PLL 输出频率怎么算"：fout = fref × N / (M × P)，讲清三个分频器分别在哪。
- 问"PLL 没锁定时怎么办"：下游保持复位，或走旁路时钟；锁定后再无毛刺切换到 PLL 时钟。
- 问"分频时钟和时钟使能选哪个"：优先时钟使能；必须分频（如给外设一个真正的低频时钟以省功耗）时用寄存器输出 + `create_generated_clock`。

**一句话**：PLL 用负反馈把低频参考倍频成高频（fvco = fref × N / M）；前端负责集成、锁定管理，并保证时钟只经过 ICG、MUX、分频器这些可控结构。

## 2. 门控时钟与 ICG

### 2.1 解决什么问题，面试怎么考

一个模块暂时不工作时，它的寄存器每个周期仍在翻转时钟引脚，时钟树也在翻转——时钟网络通常占芯片动态功耗的很大一部分（常见说法是 30%–50%，随设计而变）。**门控时钟（clock gating）**：不用时把这一组寄存器的时钟关掉，直接省掉时钟翻转功耗（`P = αCV²f` 里的 α 降为 0）。低功耗全貌见第 09 章。

面试高频问题：

1. 为什么不能用 AND 门直接门控？
2. ICG 的内部结构是什么？latch 为什么是低电平透明？
3. 用下降沿 DFF 代替 latch 行不行？
4. 综合工具怎么自动插 ICG？门控时钟对 STA、DFT 有什么影响？

### 2.2 原理：AND 门控为什么会出毛刺

使能信号 `en` 通常来自上升沿触发的寄存器，所以它**在时钟上升沿之后不久变化——此时 clk 是高电平**。`gclk = clk & en` 于是会在 clk 高电平中途变化：

```
clk      __|‾‾‾‾|____|‾‾‾‾|____|‾‾‾‾|____|‾‾‾‾|____
en       ___|‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾|________________     ← 沿后 1 ns 变化（clk 为高）
clk&en   ___|‾‾‾|____|‾‾‾‾|____|‾|________________
            ↑ 被截短的脉冲       ↑ 1 ns 的毛刺
```

- en 在高电平期间拉高 → 出现一个被截短的时钟脉冲
- en 在高电平期间拉低 → 出现一个很窄的毛刺
- 窄脉冲可能违反触发器的最小脉宽，一部分寄存器响应、一部分不响应，功能直接出错。

**要求**：en 只能在 clk 为**低**时变化（对 AND 门控而言）。

### 2.3 ICG 结构：低电平透明 latch + AND

```
               ┌───────────┐
 en ──┐        │   latch   │ en_latch  ┌─────┐
      ├─(OR)──►│ D       Q ├──────────►│     │
 se ──┘        │    EN     │           │ AND ├──► gclk
               └─────▲─────┘      clk ─►│     │
 clk ──────────o─────┘                 └─────┘
         （反相：clk 低时透明）
```

- clk 为**低**：latch 透明，en_latch 跟随 en；此时 AND 输出被 clk=0 压住，en 怎么变都不影响 gclk。
- clk 为**高**：latch 关闭，en_latch 锁住不变，所以 gclk 在整个高电平期间要么完整跟随 clk，要么保持 0。

```
clk        __|‾‾‾‾|____|‾‾‾‾|____|‾‾‾‾|____|‾‾‾‾|____
en         ___|‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾|________________
en_latch   _______|‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾|____________     ← 只在 clk 低时跟随 en
gclk       ___________|‾‾‾‾|____|‾‾‾‾|______________     ← 两个完整脉冲
```

- `se`（scan enable / test enable）：扫描测试时必须让时钟无条件通过，否则扫描链移不动。Sky130 库里就有两种 ICG：`sky130_fd_sc_hd__dlclkp`（CLK、GATE → GCLK）和带测试使能的 `sky130_fd_sc_hd__sdlclkp`（多一个 SCE 引脚），liberty 里分别标注为 `clock_gating_integrated_cell : "latch_posedge"` 和 `"latch_posedge_precontrol"`。
- 为什么叫"集成"门控单元：latch 和 AND 做在一个单元里，内部延时由库保证，工具在 ICG 的 enable 引脚上做 setup/hold 检查（见 `../07_STA/README.md` 第 9.2 节）。自己用分立的 latch + AND 拼，两者之间的走线延时无法保证。

### 2.4 RTL 讲解

`lab/Clock_Gating/clk_gate.v` 里三种写法：

```verilog
// 错误示范
assign gclk = clk & en;

// latch 型 ICG（有意推断 latch）
always @(*) begin
    if (!clk)
        en_latch = en | se;
end
assign gclk = clk & en_latch;

// 下降沿 DFF 型
always @(negedge clk) en_q <= en | se;
assign gclk = clk & en_q;
```

要点：

- latch 型的 `always @(*)` 没有 else，是**故意**推断 latch——整个仓库里只有这里允许。Verilator 会报 `LATCH` 警告，代码里用 `lint_off LATCH` 显式标注。
- 真实项目里**不要用 RTL 拼 ICG**：要么直接例化库单元（`sky130_fd_sc_hd__sdlclkp`），要么写成普通的使能寄存器让综合工具自动插（2.6 节）。RTL 版本只用于理解和仿真。
- 下降沿 DFF 型也无毛刺：en 在下降沿被采样，之后整个低电平和下一个高电平都保持。**缺点**：en 从上升沿发出，只剩半个周期就要被下降沿采到（latch 型在整个低电平期间都透明，可以借用时间），时序更紧；而且下降沿寄存器给 DFT、STA 带来半周期路径。所以工业 ICG 用 latch。

### 2.6 变体与扩展

| 话题 | 要点 |
|------|------|
| 下降沿触发寄存器的门控 | 对称地用**高电平透明 latch + OR**：`gclk = clk \| ~en_latch`，时钟停在高电平 |
| 综合自动插入 ICG | RTL 写成 `always @(posedge clk) if (en) q <= d;`，综合工具把一组共享 en 的寄存器的 D 端 MUX 换成一个 ICG。一般有最小位宽门槛（太少的寄存器不值得插），具体命令和选项以工具文档为准（如 DC 的 `set_clock_gating_style`、`compile_ultra -gate_clock`） |
| 多级门控 | 模块级粗粒度门控 + 寄存器组级细粒度门控，可以级联 |
| 对 STA 的影响 | ICG 输出仍是同一时钟（不需要新建时钟），但工具会在 ICG enable 端做 clock gating setup/hold 检查；ICG 后的时钟树要和其它分支平衡 skew |
| 对 DFT 的影响 | 必须有 test enable（SE/SCE），否则扫描模式下时钟可能被关掉 |
| 门控使能的时序 | en 路径是"上升沿寄存器 → ICG latch"的路径，要在下一个上升沿前稳定（latch 型最晚到 clk 上升沿前的 setup 时间） |

### 2.7 面试要点与常见追问

- **为什么不能用 AND 门控**：en 来自上升沿寄存器，在 clk 高电平时变化 → 截短脉冲和毛刺。本实验里最窄 1 ns。
- **ICG 里 latch 为什么是低电平透明**：clk 低时 AND 输出被压为 0，en 随便变；clk 高时 latch 锁住，保证整个高电平期间使能不变。
- **能不能用下降沿 DFF**：功能上可以，但 en 只剩半周期的时序余量，且引入下降沿寄存器；latch 型允许 en 在整个低电平期间到达。
- **ICG 放在哪里**：尽量靠近时钟树根部，关掉的时钟树越大省电越多；但 ICG 前后都要做时钟树平衡。
- **门控和使能寄存器的区别**：使能寄存器（D 端 MUX）时钟仍在翻转，只是数据不变；门控是连时钟翻转一起省掉。
- **门控时钟要不要 create_generated_clock**：一般不需要，ICG 输出被当作同一时钟的延续；但要确认工具推断出了 clock gating check。

**一句话**：en 在 clk 高电平时变化会切出毛刺，所以用"clk 低时透明的 latch 锁住 en，再与 clk 相与"的 ICG；实际设计直接用库里的 ICG 单元或让综合工具自动插。

## 3. 无毛刺时钟切换

### 3.1 解决什么问题，面试怎么考

芯片常需要在两个时钟之间切换：上电先用晶振/RC 时钟，PLL 锁定后切到 PLL 时钟；低功耗模式切到低频时钟；测试模式切到测试时钟。直接用 MUX 切，会在切换瞬间切出毛刺或窄脉冲，下游寄存器可能出错。

这是经典的**手撕代码题**：写出无毛刺时钟切换电路，并讲清楚同源和异步两种情况的差别。

### 3.2 原理

普通 MUX 为什么出毛刺：sel 变化时，旧时钟可能是高电平、新时钟是低电平，输出立刻从 1 跳到 0，形成一个截短的高电平；反之也可能出现一个窄的低电平。

```
clk0     |‾‾‾‾|____|‾‾‾‾|____|‾‾‾‾|____
clk1     ‾‾‾‾‾‾‾|_______|‾‾‾‾‾‾‾|_______
sel      ___________|‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾
out      |‾‾‾‾|____|‾|_____|‾‾‾‾‾‾‾|____
                     ↑ sel 变化时 clk0=1、clk1=0 → 窄脉冲
```

无毛刺切换要同时做到两件事：

1. **先关后开**：用交叉反馈保证当前时钟的使能先撤掉，另一个时钟的使能才能打开，两路绝不同时打开。
2. **使能只在各自时钟的低电平时变化**：用各自时钟的**下降沿**寄存器产生使能，再与时钟相与——和 ICG 用低电平 latch 是同一个道理。

切换时序（从 clk1 切到 clk0）：

```
sel      ‾‾‾‾\_____________________________________
en1      ‾‾‾‾‾‾‾‾‾‾‾\______________________________   ← clk1 下降沿撤掉
en0      _______________________/‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾   ← 看到 en1=0 后，clk0 下降沿打开
clk_out  clk1 ... clk1 | 保持低电平 | clk0 clk0 ...
```

中间有一段输出保持低电平，这是正常的（先关后开的代价），但输出上**每一段高、低电平都不会短于两个时钟中较短的半周期**——这就是 testbench 检查的标准。

### 3.3 RTL 讲解

`lab/Glitch_Free_Clock_Mux/clk_mux.v`：

**同源时钟**（两时钟有确定相位关系，如 clk 与 clk/2）：每路一个下降沿寄存器。

```verilog
always @(negedge clk0 or negedge rst_n)
    if (!rst_n) en0 <= 1'b0;
    else        en0 <= ~sel & ~en1;     // ~en1：clk1 那一路已关，才打开 clk0

always @(negedge clk1 or negedge rst_n)
    if (!rst_n) en1 <= 1'b0;
    else        en1 <= sel & ~en0;

assign clk_out = (clk0 & en0) | (clk1 & en1);
```

**异步时钟**：sel 和对侧反馈回来的 en 对本时钟来说都是异步信号，每路要先同步，多一级寄存器：

```verilog
always @(posedge clk0 or negedge rst_n)          // 第 1 级：上升沿，可能亚稳
    if (!rst_n) en0_meta <= 1'b0;
    else        en0_meta <= ~sel & ~en1;
always @(negedge clk0 or negedge rst_n)          // 第 2 级：下降沿，产生使能
    if (!rst_n) en0 <= 1'b0;
    else        en0 <= en0_meta;
// clk1 一路对称
```

常见错误：

- **忘了交叉反馈**：两路使能可能同时为 1，输出是两个时钟相或的乱码。
- **使能用上升沿寄存器**：使能在时钟高电平时变化，又回到 AND 门控出毛刺的问题。
- **异步时钟只用一级**：sel 对本时钟异步，第一级可能亚稳，亚稳的使能直接门控时钟就是灾难。
- 本实现第 1 级到第 2 级只有半个周期的恢复时间。时钟频率很高时，可以改成两级上升沿同步 + 一级下降沿寄存器，代价是切换慢一拍。

### 3.5 变体与扩展

| 话题 | 要点 |
|------|------|
| 当前时钟停了怎么办 | 使能要靠当前时钟的沿才能撤掉；如果当前时钟已经停振（比如 PLL 掉锁），en 永远撤不掉，切换卡死。需要时钟丢失检测，或者用复位强制切换 |
| 复位值 | 本实现复位时两路都关，输出没有时钟；很多设计把默认时钟那一路复位成 1，保证复位期间就有时钟（例如让同步复位能生效） |
| 多路时钟切换 | 推广到 N 路：每路使能 = 自己被选中 AND 其它所有路使能都为 0 |
| 用库单元 | 最终的 AND/OR 最好用时钟专用单元并 `dont_touch`，避免综合改结构 |
| STA | MUX 输出会同时传播两个时钟，要声明它们互斥：`set_clock_groups -logically_exclusive`（或 `-physically_exclusive`，取决于是否可能同时存在于网络上），见 `../07_STA/README.md` 第 8.4 节 |
| DFT | 测试模式下通常用 `test_mode` 强制选测试时钟，绕过切换逻辑 |

### 3.6 面试要点与常见追问

- **手写代码**：先写同源版（两个下降沿寄存器 + 交叉反馈），再说明异步时要每路加一级同步。
- **为什么用下降沿**：保证使能只在本时钟低电平时变化，AND 输出不会被截断。
- **为什么要交叉反馈**：先关后开，两路不同时开。
- **切换要多久**：大约"旧时钟 1~2 个周期关断 + 新时钟 1~2 个周期打开"，期间输出停在低电平。
- **旧时钟停了怎么办**：切换卡死，需要额外的时钟检测或复位。

**一句话**：无毛刺时钟切换 = 交叉反馈（先关后开）+ 下降沿产生使能（只在低电平变化）；异步时钟每路再多一级同步器。

## 4. 复位策略：同步复位与异步复位

### 4.1 解决什么问题，面试怎么考

复位让电路从已知状态开始。面试常问：同步复位和异步复位的优缺点；为什么业界主流是"异步复位、同步释放"；是不是所有寄存器都要复位。基本对比表已在 `../07_STA/README.md` 第 10.1 节，这里补充两个实验：**时钟停了能不能复位**，以及**综合后到底变成什么单元**。

### 4.2 两种写法在硬件上的差别

`lab/Reset_Sync/reset_styles.v`：

```verilog
// 同步复位：复位只是 D 端前面的一个条件
always @(posedge clk)
    if (!rst_n) q <= 0; else q <= d;

// 异步复位：复位接触发器的 RESET_B 引脚
always @(posedge clk or negedge rst_n)
    if (!rst_n) q <= 0; else q <= d;
```

用 Yosys 把两个 8 bit 寄存器分别综合到 Sky130 hd 库（`synth_reset.ys`），实际单元统计：

```
== reg_sync_rst ==
        8   50.048   sky130_fd_sc_hd__and2_0
        8  160.154   sky130_fd_sc_hd__dfxtp_1
   Chip area for module '\reg_sync_rst': 210.201600
== reg_async_rst ==
        8  200.192   sky130_fd_sc_hd__dfrtp_1
   Chip area for module '\reg_async_rst': 200.192000
```

- 同步复位 = 普通 DFF（`dfxtp`，无复位端）+ 每 bit 一个 AND 门（`d & rst_n`）。复位信号进入**数据路径**，占用 D 端的组合逻辑时间。
- 异步复位 = 带异步复位端的 DFF（`dfrtp`，RESET_B 引脚）。复位**不在数据路径上**，但释放要满足 recovery/removal。
- 面积：在这个库里异步复位版本反而略小（200.2 vs 210.2 µm²），因为一个 `dfrtp_1`（25.0）比 `dfxtp_1 + and2_0`（20.0 + 6.3）小。"同步复位省面积"要看库，不是定论。

### 4.3 时钟停了能不能复位

`tb_reset_sync.v` 的 Part 2：寄存器先写入 `A5`，然后在时钟低电平时停振，再拉低 rst_n：

```
Part 2  clock stopped, rst_n=0 : q_async=00  q_sync=a5
Part 2  first edge after restart : q_async=00  q_sync=00
```

- 异步复位立即清零，不需要时钟。
- 同步复位在没有时钟时**无效**，直到时钟恢复后的第一个上升沿才清零。

这就是"上电时 PLL 还没锁定、时钟还没起振"场景下偏好异步复位的原因。

### 4.4 优缺点总结（在 07 章表格基础上补充）

| | 同步复位 | 异步复位 |
|--|----------|----------|
| 无时钟时能否复位 | 不能（实验 4.3） | 能 |
| 复位路径 | 进入 D 端数据路径，占时序（实验 4.2 的 AND 门） | 不占数据路径，但释放要满足 recovery/removal |
| 毛刺 | 只在时钟沿采样，不敏感 | 复位线上的毛刺会直接误复位 → 复位引脚要做滤波 |
| 复位脉宽 | 至少覆盖一个时钟沿（通常要求多个周期） | 任意短都有效 |
| 释放时的问题 | 无（本身就是同步的） | 释放落在时钟沿附近 → 亚稳态、各寄存器不在同一周期退出复位 → 要复位同步器（第 5 节） |
| STA | 普通 setup/hold | recovery/removal（`../07_STA/README.md` 第 9.1 节） |

**结论**：业界主流是**异步复位、同步释放**：复位拉起走异步（不依赖时钟、立即生效），释放经复位同步器对齐到时钟沿（避免 recovery/removal 问题）。

### 4.5 其它常被追问的策略

- **不是所有寄存器都要复位**：控制通路（状态机、计数器、valid 标志）必须复位；纯数据通路寄存器（被 valid 限定的数据、流水线数据）可以不复位，省面积、减轻复位树负担。前提是在 valid 有效前没有人使用它们的值。代价是仿真中它们上电为 X，要确认 X 不会传播到控制逻辑。
- **复位来源**：上电复位（POR，模拟电路检测电源上升）、外部复位引脚、看门狗、软件复位。通常由一个复位控制器汇总、滤波、按顺序释放。
- **复位引脚滤波**：外部复位引脚可能有毛刺，用模拟滤波或数字滤波（连续 N 个周期为低才认为有效）去除。
- **复位释放顺序（reset sequencing）**：先等电源稳定、PLL 锁定，再释放总线和核心，最后释放外设；每个时钟域有自己的复位同步器（第 5 节）。

### 4.6 面试要点与常见追问

- **同步/异步复位各自优缺点**：按 4.4 节表格讲，重点是"无时钟能否复位"和"释放问题"。
- **为什么用异步复位同步释放**：兼得两者优点——拉起不依赖时钟，释放不违反 recovery/removal。
- **同步复位综合后是什么**：DFF + D 端的 AND/MUX（本实验 8 个 `and2_0`）。
- **所有寄存器都要复位吗**：控制通路要，数据通路可以不要。

**一句话**：同步复位是 D 端的一个 AND，需要时钟；异步复位接 RESET 引脚，不要时钟但释放有风险；主流做法是异步复位、同步释放。

## 5. 复位同步与 RDC

### 5.1 解决什么问题，面试怎么考

异步复位的**释放**如果落在时钟沿附近，会违反 recovery/removal：某些寄存器在这个沿退出复位，另一些在下个沿退出，状态机可能进入非法状态；寄存器本身也可能亚稳。复位同步器（reset synchronizer）让释放与本时钟域对齐。

**RDC**（Reset Domain Crossing，复位域交叉）是另一个层面的问题：即使在**同一个时钟**下，一个寄存器被异步复位时，它的输出会在任意时刻变化，下游**没有被复位**的寄存器可能采到这个变化而亚稳。

面试常考：手写复位同步器；解释为什么 D 端接常量 1；多时钟域怎么复位；什么是 RDC。

### 5.2 原理：异步复位、同步释放

```
             1'b1
              │
         ┌────▼────┐       ┌─────────┐
         │ D     Q ├──────►│ D     Q ├──────► srst_n（给本时钟域所有寄存器）
  clk ──►│>  sync0 │  ┌───►│>  sync1 │
         │  RST_N  │  │    │  RST_N  │
         └────▲────┘  │    └────▲────┘
              │      clk        │
 arst_n ──────┴─────────────────┘
```

```
clk      _|‾|_|‾|_|‾|_|‾|_|‾|_|‾|_|‾|_|‾|_
arst_n   ‾‾‾‾‾‾\_______/‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾   ← 拉低、释放都是异步的
sync0    ‾‾‾‾‾‾\_________/‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾   ← 释放后第 1 个上升沿打进 1（可能亚稳）
srst_n   ‾‾‾‾‾‾\_____________/‾‾‾‾‾‾‾‾‾‾‾‾   ← 立即拉低；第 2 个上升沿才释放
```

- 拉起：`arst_n` 直接接到两级的异步复位端，srst_n **立即**有效。
- 释放：常量 1 从 D 端逐级移入。第一级在 arst_n 释放时可能违反 recovery 而亚稳，第二级再给一个周期恢复，srst_n 的上升沿与时钟对齐。
- srst_n 到本域各寄存器 RESET 端的路径是**同步路径**，由 STA 的 recovery/removal 检查覆盖。

### 5.3 RTL 讲解

`lab/Reset_Sync/reset_sync.v`：

```verilog
module reset_sync #(
    parameter STAGES = 2          // >= 2；高频或 MTBF 要求高时用 3
)(
    input  clk,
    input  arst_n,
    output srst_n
);
    reg [STAGES-1:0] sync;

    always @(posedge clk or negedge arst_n) begin
        if (!arst_n)
            sync <= {STAGES{1'b0}};
        else
            sync <= {sync[STAGES-2:0], 1'b1};
    end

    assign srst_n = sync[STAGES-1];
endmodule
```

常见错误写法：

| 错误 | 后果 |
|------|------|
| 把 arst_n 接到 D 端，用普通两级同步器 | 复位拉起也要等两个时钟沿，时钟没起振时复位不了 |
| 第一级 D 端接 arst_n 而不是常量 1 | arst_n 进入数据路径，CDC/RDC 工具会把它报为未同步的异步信号 |
| 多个时钟域共用一个复位同步器 | 同步释放只对它自己的时钟有效，对别的时钟仍是异步释放 |
| srst_n 再经过组合逻辑（比如和软件复位相与）才送到寄存器 | 组合逻辑的毛刺直接造成误复位。要合并多个复位源，应在同步器的 **arst_n 输入端**合并 |

综合结果（同一脚本）：两级同步器就是两个 `dfrtp_1`，D 端接常量：

```
== reset_sync ==
        2   50.048   sky130_fd_sc_hd__dfrtp_1
   Chip area for module '\reset_sync': 50.048000
```

### 5.4 仿真

```bash

```

Part 1 同时例化 STAGES=2 和 STAGES=3 两个同步器，arst_n 在随机时刻拉低/释放 60 次，其中三分之一的复位脉宽短于一个时钟周期。testbench 用逐拍参考模型检查：

- arst_n 拉低后 1 ps 内 srst_n 必须为 0（拉起不依赖时钟）；
- srst_n 只在 clk 上升沿释放，而且恰好是 arst_n 释放后的第 STAGES 个上升沿；

实际输出：

```
Part 1  asserts=61  releases STAGES=2: 50 (expect 50)  STAGES=3: 45 (expect 45)
Part 2  clock stopped, rst_n=0 : q_async=00  q_sync=a5
Part 2  first edge after restart : q_async=00  q_sync=00
```

61 次拉起（含上电那一次）只释放了 50 次（两级）和 45 次（三级）：其余几次 arst_n 高电平太短，同步器还没来得及释放就又被复位。级数越多，要求复位释放后保持的时间越长。

两个 testbench 细节：

- 一开始把 `arst_n` 在声明时初始化成 0，结果同步器一直是 X——声明时的初始化不产生 negedge 事件，异步复位 always 块不会被触发。改成先为 1、再在 initial 里显式拉低一次。真实芯片上电时也必须有一次实际的复位有效。
- 随机时刻要避开时钟沿（`rand_wait` 任务）：零延时仿真里 arst_n 与 clk 同时变化是仿真竞争，不代表真实硬件行为。**RTL 仿真表现不出亚稳态**，同步器是否安全靠结构和 STA/CDC 检查保证，而不是靠仿真。

波形建议看：`clk`、`arst_n`、`u_rs2.sync`、`srst2_n`、`srst3_n`。

### 5.5 复位树与多时钟域

- **复位树**：srst_n 要驱动本域所有寄存器，扇出巨大。`../07_STA/README.md` 第 15.2 节的 lab 里，一个 buf_2 驱动几百个 RESET_B，slew 达到 3.74 ns、recovery 裕量只剩 0.498 ns。真实流程要像时钟树一样插 buffer 树（不必平衡 skew，但要满足 slew 和 recovery/removal）。
- **每个时钟域一个复位同步器**：

```
              ┌──────────────┐
 arst_n ──┬──►│ reset_sync   ├──► srst_a_n  （clk_a 域）
          │   │   clk_a      │
          │   └──────────────┘
          │   ┌──────────────┐
          └──►│ reset_sync   ├──► srst_b_n  （clk_b 域）
              │   clk_b      │
              └──────────────┘
```

- **释放顺序**：若要求 B 域在 A 域之后释放，把 A 域同步后的复位作为 B 域同步器的 arst_n 输入（或与全局复位相与后输入），形成级联。
- **复位期间的时钟**：复位同步器释放需要时钟沿；如果复位期间时钟被门控关掉或还没切换好，复位就一直释放不了。

### 5.6 RDC：复位域交叉

**定义**：发送寄存器和接收寄存器属于不同的**复位域**（被不同的异步复位控制），即使它们在同一个时钟域。

```
             rst_a_n（异步有效）          rst_b_n（此时没有复位）
               │                            │
clk ──►[FF_A]──┴──► 组合逻辑 ──────►[FF_B]──┴──► ...
          │                            ▲
          └──────────── clk ───────────┘
```

**问题**：rst_a_n 在任意时刻拉低时，FF_A 的 Q 立即变化——这个变化与 clk 没有任何时序关系。如果恰好落在 FF_B 的 setup/hold 窗口内，FF_B 就会亚稳，而 FF_B 并没有被复位，错误会留在系统里。STA 帮不上忙：rst_a_n 的拉起来自异步源（外部引脚、其它时钟域的软件复位等），和 clk 没有确定的相位关系，这类路径通常被设成 false path 或不受约束，STA 给不出有意义的检查。

**典型场景**：软件单独复位某个外设（外设复位域），而总线接口（系统复位域）还在工作，外设输出的状态信号被总线侧寄存器采样。

**解决办法**：

| 方法 | 做法 |
|------|------|
| 复位顺序约束 | 保证 rst_a 有效时 rst_b 也有效（接收端同时或先复位），让接收端在发送端乱变时处于复位中 |
| 隔离/门控 | rst_a 拉起前，先用同步的使能信号让 FF_B 停止采样（或关掉 FF_B 的时钟），等 rst_a 释放并稳定后再恢复 |
| 同步器 | 把 FF_A 的输出当作异步信号，在接收端加同步器（和 CDC 同样的处理） |

**检查工具**：专门的 RDC 静态检查（如 Questa RDC、SpyGlass RDC、Meridian RDC 等，具体规则以工具文档为准）会找出所有"复位域不同的寄存器对"，要求设计者给出复位顺序约束或确认有隔离。

### 5.7 面试要点与常见追问

- **手写复位同步器**：两级、D 端接 1、异步复位端接 arst_n，输出给本域使用。
- **为什么 D 端接 1 而不是 arst_n**：arst_n 只作用在异步复位端，不进数据路径；拉起立即生效，释放时 1 逐级移入。
- **第一级也可能亚稳，为什么没事**：第二级给了一个周期恢复时间，和两级同步器的道理相同（MTBF 分析见 `../06_CDC/README.md` 第 1 节）。
- **复位同步器输出要不要 STA**：要，srst_n → 各寄存器 RESET 端是同步路径，做 recovery/removal 检查。
- **多时钟域怎么复位**：每个域一个复位同步器；有顺序要求时级联。
- **RDC 和 CDC 的区别**：CDC 是时钟不同导致的异步；RDC 是同一时钟下，异步复位拉起让信号在任意时刻变化。解决思路类似：隔离、顺序、同步。

**一句话**：复位同步器"拉起异步、释放同步"，每个时钟域一个；RDC 是同时钟下异步复位造成的亚稳风险，靠复位顺序、隔离或同步器解决。
